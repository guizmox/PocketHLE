PocketHLE — lancement générique des applications PocketPC sans installation CAB

Copier ces TROIS fichiers à leur emplacement dans le dépôt, puis recompiler :
crates/pocket-library/src/lib.rs
frontends/pocket-android-jni/src/runner.rs
frontends/pocket-desktop/src/runner.rs

Les deux fichiers frontends/ font partie du correctif. Remplacer uniquement pocket-library ne modifie pas le lancement du GUI.

Cause : les applications ZIP sans install_dir ne recevaient pas de montage de sauvegarde au-dessus de leurs fichiers installés. Une ouverture en lecture/écriture pouvait échouer malgré la copie sur écriture déjà présente dans le VFS. Le nom de module et le répertoire courant pouvaient également rester ceux du programme fictif Game.exe.

Correction : chemin de module réel, répertoire courant du véritable exécutable (y compris les sous-dossiers), montage de sauvegarde isolé pour les applications PocketPC portables. Chemins CAB et emplacements de sauvegarde déclarés conservés. Les cartes Gizmondo sans install_dir gardent leurs montages SD/Flash Disk.

Aucune détection de Cube, modification d'exécutable, adaptation de carte ou modification du moteur OpenGL. Les entrées déjà importées bénéficient du correctif au prochain lancement : aucune réimportation requise.

Validation :
- 106 tests pocket-library réussis, aucun ignoré (dont quatre nouveaux tests de chemins et de compatibilité).
- cargo check -p pocket-android-jni --no-default-features réussi sur l'hôte ; aucune exécution sur appareil Android revendiquée.
- ZIP Cube fourni importé via Library, puis lancé par le véritable runner PC, avec Unicorn et le rendu OpenGL actif (Mesa llvmpipe).
- Carte metl3.cgz chargée, scène texturée affichée en 640x480, arrêt propre après 35 secondes.
- Copie de sauvegarde de metl3.cgz de 8602 octets identique à la carte originale ; exécutable original inchangé.
- Vérifications effectuées dans un profil local de diagnostic ; les ajustements temporaires de compilation et les sondes ne sont pas livrés.
