# Ultima Underworld: MFC and fixed-stylus turns (20 November 2026)

Base: `b24d80122d4dc7607dce69e1a8348f918b75a99d`, branch `snapshots`.
The cumulative source package also includes the earlier 0.5.0 changes.

## Diagnosis

The supplied ARM executable's input poll at `0x579e4` returns -1 when
PeekMessage reports an empty queue. Its mouse-processing path therefore stops
advancing during a stationary held contact. The same executable handles WM_PAINT
at `0x778fc`, draws through GAPI, and does not validate the client update region.
The old HLE consumed that invalidation when retrieving its first paint. Keyboard
repeat and moving-stylus messages hid the resulting starvation.

Windows CE keeps generating paint messages until the update region is validated:
[ValidateRect CE3](https://learn.microsoft.com/en-us/previous-versions/ms915503(v=msdn.10))
and [PeekMessage CE3](https://learn.microsoft.com/en-us/previous-versions/ms961300(v=msdn.10)).
The new shared state retains client update rectangles independently of retrieval.
Input and posted messages keep priority. BeginPaint, ValidateRect and default
painting consume the region; an internal paint alone remains a one-shot event.
GetUpdateRect reads the actual pending bounds, and duplicate/partial invalidations
reuse the existing rectangle operations. The renderer's existing DC clipping and
background-erase policies otherwise remain in place.

Retaining the update alone also exposed duplicate LCD waits: the window paint
calls GXEndDraw, and the engine's own image calls it again. DispatchMessage now
records the real message ID in its continuation frame. A GAPI WM_PAINT redraw
publishes actual pixels without claiming another game frame or another LCD
wait. Ordinary and timer-driven presentations retain their existing pacing,
including unchanged frames. No executable-name branch, fixed-PC interception,
artificial mouse motion or repeated touch-down is added to production code.

## Measurements

Native ARM runs on the Linux headless test host, from the supplied corridor
state, hold the same left input from 1000 to 3000 ms. Numbers below are changed
framebuffer revisions near those boundaries, not the displayed FPS counter.
The counter can report 60 while the game keeps presenting unchanged pixels.

| Path | Held stylus | Held left key |
| --- | ---: | ---: |
| Before | 2 | 58 |
| Retained invalidation only, diagnostic prototype | 29 | 20 |
| Retained invalidation plus repaint/presentation distinction | 43 | 56 |

The incomplete prototype was not delivered: the second fix removes its keyboard
slowdown. A newly captured section-11 slot was then restored by the production
reader with no diagnostic invalidation injection; the same stylus input produced
44 changed revisions. A right-contact run also produced 43 changes and a visible
turn. These are controlled in-game checks, not a physical Windows/Android or GPU
throughput benchmark. The ordinary keyboard behavior is preserved; keyboard
repeat and a fixed mouse contact remain distinct native game inputs.

## MFC

At the tested revision, retail CE3 exports covered CArchive construction and
destruction, buffered Read / Write, ReadCount / WriteCount and CByteArray
serialization. They operated on the existing CFile/VFS descriptions and guest
heap. CObject's base runtime class was registered, and CFile's hidden CString
result used the verified ARM this/out
argument order. The supplied retail/debug DLLs were ABI evidence; their ordinal
maps are not conflated and no runtime DLL is distributed.

The 10 MFC tests include inline archive cursor advances, read-ahead rewind,
owned versus supplied buffer release, count markers, file round-trip and cleanup.
General object graphs and guest CFile virtual-I/O subclasses were outside the
bridge at that revision. The current bridge includes supported object graphs
and guest CFile virtual dispatch; see [MFC](../MFC.md) for its present contracts
and remaining limits. The counts above describe the historical test set.

## Snapshots and delivery

WinCE kernel section 11 captures the update rectangles, dispatched message ID
and BeginPaint erase-continuation rectangle. The native core round-trip test
checks that these survive a cold restore. EGL section versions are unchanged.
No older kernel-version reader is retained during this development stage.

The supplied old slot had no retained update region under its earlier HLE.
A local diagnostic import re-established one client invalidation and captured
a new slot before injecting gameplay input. The resulting slot was tested with
the production reader. The diagnostic deserialization annotations, converter
and probes are excluded from the source package. The optional rebuilt slot
requires the original executable/data and the normal strict VFS checks.

## Validation and limits

- 794 WinCE tests passed; 35 hardware/context-dependent tests ignored.
- 420 kernel tests passed.
- 34 native core tests passed; 2 context-dependent tests ignored.
- Desktop and Android JNI host checks passed with Unicorn.
- MoonGBA displayed its native menu, Prey reached the main menu and Brothers in
  Arms reached the Normandy mission loading screen in native ARM regression runs.
- Stuntcar Extreme ran its GLES path for 20 seconds, produced 877 completed
  presentations and reached name entry with real game graphics. This Linux host
  uses Mesa llvmpipe for headless GL testing; no physical-GPU speed is claimed.
- The packaged rebuilt slot was opened through the real launcher slot reader,
  restored and exercised with the same held-stylus input.
- The existing Android Kotlin/controller unit code is unchanged by this follow-up;
  its last run passed 122 tests. No new physical-device validation is claimed.

The initial cold diagnostic harness omitted the game's save overlay and returned
-24 after a failed SAVE0 directory search. With the same save/application-data
mounts as the GUI, a fresh native ARM launch reaches the Ultima main menu and
continues for 14 seconds. Its 26k-call trace contains only handled/trampolined
calls, with no missing API or CPU exception. This was a harness configuration
correction, not an additional production workaround.
