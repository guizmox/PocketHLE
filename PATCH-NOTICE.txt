PocketHLE - Colors Language R1

Overlay based on repository commit: 31bb2e4f45ffa81597297b9b43a1163db2718519

Extract at the PocketHLE repository root, overwriting the listed source files.
Close the emulator first. No files need deletion.

Windows CMD:
powershell -NoProfile -Command "Get-Content 'removed-files.txt' | ForEach-Object { if (Test-Path -LiteralPath $_) { Remove-Item -LiteralPath $_ -Force } }; Get-Content 'patch-files.txt' | ForEach-Object { (Get-Item -LiteralPath $_).LastWriteTime = Get-Date }"
cargo build --release -p pocket-desktop
 target\release\pockethle-gui.exe

Android (with the existing documented build environment):
bash tools/build-android-native.sh 4
bash tools/build-android-apk.sh
Rebuild both the JNI library and APK; the settings use a new hasColors JNI method.

Gizmondo options -> Colors language
English / French / German / Italian / Spanish.
This is a saved global launcher preference, applied on the next launch.
The control is disabled unless a library entry identifies as GZGA200015.
No display-name matching and no per-game language setting.

Read-side bstrings.eng lookup redirects to its sibling bstrings.fre, .ger,
.ita or .spa. Alternate .fra, .deu, .esp names are also accepted.
Missing or case-ambiguous translation files fall back to English.
English is the default when reading old configuration files.
Other titles and write/create operations keep their original paths.
No executable or original game resource is changed; translations are not bundled.
Translation files must already be present beside bstrings.eng. This patch does
not read/replace resources stored inside data.zcd, nor merge the three newer
string keys into an older translation. The actual game archives are still needed
to confirm its resource layout and validate both versions in gameplay.
